# 第二阶段：聊天浏览器验收记录

日期：2026-10-12（北京时间）  
工程版本：0.2.0  
数据库结构版本：1，与第一阶段兼容。  
结论：第二阶段的本机聊天浏览 MVP 已完成。

## 已交付行为

- 左侧联系人列表：昵称、首字头像、最近消息、双向聊天消息总数。
- 参与者身份切换：查看该身份参与的对话，联系人摘要不引用其余两人之间的聊天。
- 双向聊天气泡：区分当前身份发送与接收的消息，按时间升序显示日期和北京时间。
- 当前聊天及全部聊天搜索，全部聊天结果可跳转到来源会话。
- 日期筛选：开始与结束日期均包含在内，按北京时间解释；反向日期范围显示错误。
- 每页 50 条消息，点击追加后续消息；联系人超过 50 位时可继续加载。
- 联系人按昵称或标识搜索；聊天内容按字面关键词匹配。
- 空库、空会话、无搜索结果、加载失败、重试和刷新状态。
- 桌面和窄屏适配，控件具有中文可访问名称。
- Windows 双击入口：`Run-Web-Demo.cmd` 打开演示库，`Run-Web.cmd` 打开正式库。
- 后端仅监听本机 `127.0.0.1`，没有部署、上传或外部素材请求。

页面提供只读浏览；数据增删改继续使用第一阶段的 Python 或命令行接口。真实微信导入、备份解析、群聊、媒体、导出与 AI 分析不属于本阶段。

## 实际环境与测试

Windows、Python 3.10.11、SQLite 3.40.1。浏览器自动化使用本机 Microsoft Edge，由 Playwright 驱动；Playwright 仅用于开发验证，不是项目运行依赖。

### Python / HTTP 检查

从项目目录运行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

最终结果：**45 项测试全部通过，0 失败，0 错误**。最后一次运行耗时 6.295 秒。

测试包括原有 31 项数据核心和 CLI 检查，以及新增的 14 项浏览查询/HTTP 检查：

- 联系人摘要、分页、关键词检索、未聊天联系人和自己的笔记。
- 同一查看身份不会从其余双方的聊天提取联系人最近消息。
- 双向消息、发收双方昵称、筛选后总数、时间窗口与分页。
- 105 条消息的三页读取，以及 55 位联系人的两页读取，无遗漏或重复。
- 空库、无效端口、无效或重复参数、缺少身份、不存在的联系人。
- 正确静态资源类型、HEAD 请求、缓存限制、数据库和路径遍历请求被拒绝。
- 外部 Host / Origin 访问拒绝；服务确实绑定 `127.0.0.1`。
- POST/PUT/PATCH/DELETE/OPTIONS 写入方法被拒绝，浏览请求后数据库文件字节不变。

### 浏览器实际交互

桌面视口 1440×960、窄屏视口 390×844。以下 10 组检查全部通过，未记录 JavaScript 运行异常：

1. 点击联系人、双向气泡方向、北京时间 12:01 显示。
2. 当前聊天搜索、全部聊天搜索、结果跳转到原会话。
3. 包含结束日的日期筛选、反向日期范围、无匹配结果及清除。
4. 联系人搜索、无匹配联系人和查看身份切换。
5. 延迟的旧身份请求不会覆盖新身份的聊天。
6. HTML 内容作为文字显示，不生成或执行其中的图片事件。
7. 105 条模拟消息逐页显示 50→100→105 条，无重复，结束后隐藏加载按钮。
8. 模拟消息请求断开后的错误提示与恢复重试。
9. 390 像素宽布局无页面横向溢出，联系人切换可用。
10. 实际空正式库的页面显示与刷新。

其中 HTML 注入、105 条分页与网络断开场景使用浏览器请求拦截来构造，不写入正式库或演示库；后端分页另使用临时 SQLite 数据库验证。界面截图另经视觉检查。

### 启动与打包

两个网页启动文件的数据库模式、浏览器打开调用和退出码已实际检查。自动测试替换了浏览器打开函数并让服务短时退出，避免额外打开用户窗口；网页本身已在真实浏览器中访问。

仅提取启动文件、缺少项目的情况显示中文“全部提取”提示，返回退出码 2。测试路径包含中文和空格，批处理使用 UTF-8 和 Windows CRLF 换行。

源码压缩包保留源码、静态资源、测试、使用说明、两个启动入口和空正式库/虚构演示库；排除本机虚拟环境、构建缓存和 Python 缓存。完整解压后，CLI 演示、网页首页、CSS/JS/图标和双向消息 HTTP 查询均通过验证。

0.2.0 wheel 已成功构建，实际检查包含建表 SQL 及全部网页资源。独立虚拟环境离线安装后，版本返回 0.2.0，演示重复运行维持 3/5，浏览查询返回 3 条张三双向消息，网页资源可以从安装包读取。正式库和演示库的 `integrity_check` 均为 `ok`，`foreign_key_check` 均无违规记录。

## 数据状态与限制

交付时正式库仍为 0 位联系人、0 条消息；演示库仍为 3 位虚构联系人、5 条消息。核心数据库没有迁移或重置。

第二阶段未做大规模性能、长期并发压力或真实微信数据兼容性验证。SQLite 仍是明文文件，没有登录、数据库加密和自动备份。本机监听和浏览器跨域限制不等同于抵御本机其他程序访问。

下一阶段应先增加标准格式导入及字段映射、去重和导入报告，再单独研究真实微信备份格式。

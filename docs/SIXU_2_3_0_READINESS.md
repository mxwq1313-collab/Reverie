## 原生合并实验与剩余瓶颈

原生线程 CPU 按内核/用户时间采集，GDI/USER 资源、窗口消息时序与墙钟调用栈分开记录。Tk 的 `MoveWindow(TRUE)` 会同步调用 `UpdateWindow`；采样出现窗口移动、设备上下文和调色板路径。墙钟样本包含正常等待，不能按样本比例宣称 CPU 占用，更不能据此判定驱动故障。[MoveWindow 语义](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-movewindow)、[Tk 8.6.12 子窗口事件处理](https://github.com/tcltk/tk/blob/core-8-6-12/win/tkWinX.c)。

| 实验 | 有效结果 | 采用结论 |
|---|---|---|
| 原生回调直接调用 Python Tk 调度 | 发生线程状态/GIL 崩溃 | 排除 |
| WM_TIMER 16 ms 合并 | 52 次变化只刷新 2 次，消息饥饿 | 排除，不能用少刷新制造快数据 |
| PostMessage 合并 | 外层长消息/转发/Markdown 两轮 P95 中位数约 132.647→91.410、97.421→69.035、84.593→53.420 ms；内部三轮约 79.639→57.320 ms | 人工反馈仍有黑条、闪块或布局异常；不启用到应用。仅 `tools/windows_paint_candidate.py` + 显式 `--batch-paint` 可诊断 |
| 直接 `Tcl_DoWhenIdle` | 两轮前台内部 P95 79.826→59.807 ms；线程 CPU 2601.563→2562.500 ms；6 项生命周期通过 | WGC 抽样发现移动后的 AI 标题与控件残缺，排除该原型 |
| Tcl idle + 移动子树完整重绘 | AI 标题/控件在抽样帧中恢复；209 帧录像解码通过、无队列丢帧；6 项生命周期通过 | 没有据此认定所有帧或流畅度通过 |
| 只补实际移动的子树 | 两轮同窗、反向顺序对照：P95 73.594→63.822 ms，最大间隔中位数 102.287→96.956 ms；CPU 2718.750→2507.813 ms。四次均前台、26 个实际宽度、无回调错误 | 约 13% 的间隔改善仍不足以宣布解决；原型仅在忽略的 `build/r231/`，生产源码未采用 |
| 限制转发 Text 绘制表面、复用实际 Text 测量 | 表面在样例中本来就小，复用测量仅一组约 85→79 ms | 无足够整体收益，不改生产语义 |
| CS_OWNDC | 独立合成进程在表情图片渲染时失败，finally 恢复，进程退出 | 排除，不改系统/应用窗口类 |
| 隔离 Tcl/Tk 8.6.15 | 官方签名安装包只解包到 build，单轮 P95 80.378 ms，无明显收益 | 未运行安装器，未替换应用运行时 |

父窗口移动后，原生坐标未变的子控件也需要恢复显示；只 invalidating 直接发生位置变化的 HWND 会遗漏它们。补齐子树后抽样残缺消失，说明先前更快结果混入了绘制不完整的收益。不能把它直接当作可发布优化。

原始纯计时：`build/r231/native_live_compare.json`、`tcl_idle_held_fixed.json`、`tcl_exposure_compare.json`；失败和无效数据保留。此前时间戳为 0 导致拖动被识别成双击、宽度未变化的快结果已排除；丢失前台的矩阵也未纳入验收。

## 录像验证

采用 `tools/windows_resize_capture.py` 的首帧门控、隐藏/最小化拒绝、正常收尾及完整 VFR 解码；可选 `windows_resize_wgc.py` 使用 HWND 限定的 Windows.Graphics.Capture、无损 RGB、原像素补边、原生帧时间戳和队列丢帧计数。依赖放在 `build/r231/capture_deps`，没有加入应用环境和发行包。

- 普通实时分栏 `internal_wgc.mkv`：204 帧、约 4.41 秒、零队列丢帧、完整解码通过；AI 拖动时联系人固定区域逐帧哈希相同。这只证明该区域/该场景。
- 人工普通候选 `human_live.mkv`：178 次内部宽度变化、21 次外层尺寸变化；用户“黑条消失，但仍明显卡顿”。GUI CPU 12.984 秒，16 ms 心跳 P95 55.827 ms、最长 163.783 ms。结束时窗口最小化，整段录制状态如实失败，保留之前有效画面，不能声称全段通过。
- 人工 PostMessage 组合 `human_combined.mkv`：881 个源帧、零丢帧、完整解码通过；151 次内部分栏变化，变化时窗口均前台；用户“仍有黑条、闪块或布局异常”。录像技术通过，人工视觉验收失败。未出现有效外边框变化，不虚构该项完成。
- Tcl idle `tcl_idle_wgc.mkv`：192 帧、4.278 秒、零队列丢帧、解码通过；抽样存在 AI 控件残缺。`tcl_idle_contact_sheet.png` 保留了失败画面。
- 补子树 `tcl_subtree_wgc.mkv`：209 帧、4.758 秒、零队列丢帧、解码通过；抽样 AI 控件恢复。固定联系人 ROI 逐帧一致不能代替动态区域验证。
- 实际移动子树人工录像 `human_exposure`：最新结果与用户反馈见本文件末尾及工作状态。

WGC 在内容更新时出帧，请求最小 8 ms 不等于达到 120 fps；上述录像实际约 44–46 次更新/秒。GDI 捕获曾达到约 78–82 fps，但会捕获部分绘制中间态。心跳间隔、捕获更新率均不等于屏幕呈现帧率，不能据此声称流畅或全部瞬态消失。视频外部黑色补边不是应用黑块。离线黑色像素启发式没有检测到异常，也不能推翻人工看到闪块的反馈。

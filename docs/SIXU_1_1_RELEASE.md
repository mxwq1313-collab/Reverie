# 思绪 1.1.0 发布与验收

2026-10-15。基于 1.0 修复提交 73f3878，按本次用户要求发布 1.1.0；保留旧发行包和 v1.0.0 标签。

## 使用变化

1. 用户消息在右侧，Codex 回答在左侧；回答生成中显示 `● · · 正在回复…`，符号依次轮换。减少动画设置下使用静态符号。完成、停止、断线和关闭时取消提示；提示不会进入复制、导出或历史正文。
2. 修复独立 Codex 运行配置关闭 Code Mode host 的问题，保持系统执行、文件编辑和其他账号读取禁用。每次提问先从当前授权归档实际读取一批原文，附消息编号、总数和覆盖范围；最多50条且仍受工具字符预算限制。默认取最近一批，界面存在日期或关键词筛选时按筛选查询；未读取部分继续通过只读工具分页，不能将一批材料称为全部历史。切换身份、会话或原文版本后撤销旧授权。
3. 添加页直接使用“一键读取（含图片/表情）”。图片使用已登记组件读取本地最高可用档位；修复输出到总目录后又到逐消息目录检查的路径错误，支持文本XML中的图片MD5。本地表情按消息声明MD5在所选账号与共享表情缓存中精确匹配，核验字节与可解码格式；支持GIF动画、PNG、JPEG和WebP。缩短逐消息临时目录，降低Windows路径长度压力。
4. 提供随包的本地HEVC解码器，已解密wxgf图片可生成JPEG预览，同时保留wxgf容器供保存与导出。未取得的缓存、不能解码的容器明确保留状态，不用空白占位伪装成成功；结果区同时显示附件取得、缺失与异常数量。重读同一来源可以补齐原来缺失的附件，消息按原来源ID去重。
5. 已打开页面切换复用现有控件，仅首次进入处理该页面的本地化，避免每次遍历全窗口。流式事件在每轮轮询中合并渲染；长回答在布局完成后跟随，用户上翻时保持阅读位置。

Codex协议依据[官方App Server说明](https://learn.chatgpt.com/docs/app-server)核对；动态工具仍属于实验接口。图片转换使用[imageio-ffmpeg 0.6.0](https://pypi.org/project/imageio-ffmpeg/0.6.0/)提供的本地二进制，发行包附第三方许可信息。

视觉：已用Computer Use查看900×720窄窗口和1240×820宽窗口，检查左右排列、符号提示、长回答跟随及引用。全部为自建数据窗口。最终宽窗口截图保存在本机构建证据中，不将真实聊天截图放入Git。

## 使用与边界

关闭旧版后运行新文件夹内的“思绪.exe”，保留同目录_internal。Codex重新连接时自动应用新配置，现有登录与归档仍可使用。添加记录选择已连接账号与联系人/群聊，再选最近50条、500条或全部电脑本地记录，点击一键读取。

之前归档只保存文字或缺失附件的会话，需要对原来源重新读取，副本中的缺失文件无法凭空恢复。微信尚未缓存的图片或表情仍显示未取得，可以先在微信中查看后重读；本版不抓取消息XML里的远端URL。测试没有读取用户真实微信库，因此当前微信账号、历史资源留存情况与全部专有容器兼容性仍需在实际来源使用中核对。

图片和表情在本地归档中显示、保存及离线导出。Codex读取正文和附件元数据，原文件不会因本次改动自动上传做视觉识别。未知数据库、加密/损坏来源与未登记格式继续明确拒绝，不把解密逻辑混入解析。

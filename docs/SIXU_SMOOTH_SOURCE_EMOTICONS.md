# 思绪 2.0.0 流畅度、来源读取与内置表情修复验收

2026-10-16。基于 `bf23971`，沿用 `feature/sixu-mbti-ui`。这是本地修复构建，正式版本仍为 2.0.0，不新建正式标签、不推送。源码、验收与构建均位于实际源码仓库。

## 修改与原因

1. 原来的富媒体读取同时监视整个账号数据库和 WAL，消息投影、媒体恢复期间任何变化都会以同一条“来源变化或不可读分片”错误退出。新实现仍调用固定摘要核验的 SDK，不实现新的解密逻辑；在单个数据库建立副本期间检查来源稳定性、完整性和 SDK 降级告警，最多重试 3 次。成功后只复用本次工作目录内的不可变只读副本；后续新消息不再使长期媒体提取作废。副本被改动、日志未封存、分片清单变化或最终仍不完整均继续拒绝。
2. 真实环境验证发现：微信数据库副本可以保留 WAL 模式头，普通只读连接在查询时创建空 WAL/SHM，导致封存检查误报。现在先关闭 SDK 连接，再以 immutable 只读连接校验、查询，避免新建这些侧文件。各分片分别建立稳定视图，不宣称整个账号跨库处于同一个原子时间点；读取后收到的新消息需再次读取。
3. 来源群成员从一次性创建全部行改为展开后每批 50 行；来源会话每批 60 行，可在切换账号、结果替换或销毁窗口时撤销待处理任务。正常客户端的聊天排版按约 6ms 工作预算让出事件循环，切换页面取消旧排版，布局完成后再恢复滚动。显式同步控制器继续保持既有同步语义。
4. 新增 109 个微信内置文字表情的离线图像。`[流泪]`、`[捂脸]` 等支持与普通文字混排、重复表情、换行和字号变化。图像覆盖原 token 的显示，原文仍可选择、复制和检索，数据库正文、去重身份与导出保持原样；未知方括号文字仍显示原文。旧归档无需重新导入。第三方资源来自 [xxk8/wechat-emojis](https://github.com/xxk8/wechat-emojis)，保留其个人学习、非商业用途及图像版权声明，归档和每张原图摘要写入本地资源清单。

## 流畅度对照

同一设备、相同自建数据、修改前 `bf23971` 实现与最终实现对照。180 个群、每群 500 个成员，均保持默认折叠；300 条长文本用于字号重排，双方均启用正常客户端的后台浏览与离屏折叠。测试窗口不可见，不把此基准解释为整个程序或所有设备的帧率。首次独立控件对照未启用离屏折叠，其原始回执另存，最终表使用相同正常模式。

| 测量 | 修改前 | 修改后 |
|---|---:|---:|
| 来源列表首次回调 | 354.623 ms | 0.448 ms |
| 折叠状态下创建的树行数 | 90180 | 360 |
| 字号重排首次回调 | 18406.054 ms | 47.4 ms |
| 字号重排总耗时 | 18820.135 ms | 24074.621 ms |
| 重排期间事件循环最大间隔 | 18407.36 ms | 152.032 ms |

回调返回、事件循环响应和最终排版完成是不同测量。缩短阻塞不代表所有像素立即绘制完毕。本轮优先减少连续阻塞；此压力场景的总重排耗时增加，仍需后续优化，不能宣称所有性能指标都改善或已达到稳定 60fps。

## 真实来源验收

只复核截图失败任务原先选定的同一个群、最近 5 万条范围，全程关闭 CDN。成功封存 44695 条，隔离归档新增 44695 条、失败 0 条；再导入识别 44695 条重复，无重复入库。数据库 integrity_check=ok，用户原归档摘要不变，没有向模型发送真实聊天。单独建立副本和隔离导入，不自动合并用户原归档。

共 7333 个附件引用，其中 5312 个离线取得、2021 个本地缺失，处理异常 0。资源缺失继续明确保留；图像、GIF 原有获取和播放能力由兼容回归与 EXE 入口另行验收。内置文字表情与需获取文件的自定义贴图分别处理。

首次真实复核暴露空 WAL/SHM 问题；随后遇到 SDK 临时降级，加入有限重试后完整读取成功。首次深目录隔离导入触及 Windows 路径长度限制，换用仓库 `build/sf/a.db` 短测试路径后通过，没有改变系统配置。各次失败与最终成功回执均保留在被 Git 忽略的 build 目录。

## 操作入口

完整解压新的 v0.6.0 ZIP，双击 ChatArchive.exe，保留 `_internal`。打开后为欢迎页，左侧导航包含以下全部已实现能力：

| 页面 | 操作 |
|---|---|
| 欢迎 | 新建/打开归档，查看记录数量，进入常用操作 |
| 电脑微信 | 检测账号、选择账号、加载/搜索联系人、选择私聊和读取范围、读取并归档、取消读取 |
| 聊天归档 | 切换身份、联系人、原生对话显示、关键词、日期、全部/当前会话搜索、加载更多 |
| 导入文件 | JSON/CSV/已有适配输入、预览、严格模式、账号标签/时区、原校验/去重/报告 |
| 可读导出 | 全部/当前身份/当前会话，HTML/TXT/两者，显示时区，新目录不覆盖 |
| 数据管理 | 联系人及消息新增/修改/删除，关联删除拒绝，删除确认；只影响归档副本 |
| 备份检查 | RMFH 结构、文件头、有限载荷检查；正文未解密时明确显示不支持 |
| 报告与设置 | 查看本软件报告、数据目录、版本和支持范围，恢复最近归档 |

常见流程：登录电脑微信 → “电脑微信”检测账号 → 选择账号并连接 → 选择私聊 → “读取并归档” → “聊天归档”阅读 → “可读导出”保存。首次读取/导入会在明确操作时创建默认档案；预览不会创建档案。已有归档用右上角打开。

聊天显示在软件内，采用原只读查询服务，不访问外部网页或原来的本机浏览页。原网页和 CLI 留作兼容入口，没有修改其资源/协议。

## 来源与数据保护

程序包含固定 wechatauto-replica 1.2.6.1 的已审查 db.py，启动核对版本和文件摘要；只加载 DB 层，未装入发送、UI 热激活或 OCR 门面。必要 cryptography 50.0.2、zstandard 0.25.0 随包分发，附来源许可。

获取在本软件自己的工作进程运行，账号必须匹配检测列表，自身身份从联系人行核验，所选对方精确查找。原微信文件只读、解密副本独立，读取完成清理本任务副本，密钥不写缓存。取消仅终止本软件工作进程，不关闭微信；进入归档事务后等待提交完成。

默认资料位于 LOCALAPPDATA/WeChatArchive，包含 chat.db、sources、import_logs、desktop_settings.json；程序与个人资料分开。程序包不含真实聊天、账号库、密钥、工作副本或验证档案。

来源变换仍输出 chat-exchange 1.0 / LoadedDocument，随后走原 Validator、BaseImporter、去重、事务和报告。SQLite 仍为 Schema 2，没有新写库流程。未知原记录保留 raw_type/raw_payload/parse_status，不静默丢弃。编辑或删除只作用于用户选择的归档，不改变微信。

## 范围与明确限制

读取当前电脑已落地的私聊文本，不补齐仅在手机上的记录。账号/联系人接口在本机 Windows 微信 4.1.15.51 实测；其他版本未知时按失败处理。群聊、公众号、媒体、RMFH 正文以及未验证的二进制文本仍不支持。

全范围上限为 100000 项来源记录、64 MiB；联系人上限 10000。原 SDK offset 分页在真实来源出现重复窗口，本版采用其单次合并接口在明确边界内读取。超限或源消息分片变化时整批拒绝，不保存部分档案、不把读取成功伪装成全历史完成。不同来源 ID 同双方同秒同内容也按原边界拒绝，不伪造时间。

本次选定真实会话全范围超过 100000 项，拒绝检查通过，未写出来源或归档。大规模分批/断点仍是下一项工作，本版不能宣称已迁移这个私聊全部历史。

# P0 D 选定会话快照与分批恢复验收

日期：2026-10-14（Asia/Shanghai）。基线30d31d3，软件0.8.0；默认Schema2保持，流式路径需要明确打开Schema3副本。

## 已实现

新增固定SDK1.2.6.1的选定私聊投影路径：仅读取Msg加所选peer的MD5表，以及该分片Name2Id对应的实际发送者，不复制完整消息库或其他会话。原来源仍由既有隔离工作进程只读读取、密钥不落盘；快照只包含所选会话原记录，原始二进制/未知类型保留为数据，不猜正文。

每分片投影为独立SQLite，带完整清单、计数及SHA-256；新目录不覆盖，SDK来源变更/缺失分片/告警拒绝交付。快照清单/Schema/类型/路径/摘要/无sidecar/计数需通过，源SQLite以mode=ro与immutable读取，禁用写入和扩展。

跨分片按时间、来源序、分片和局部ID稳定归并；每片keyset游标，不循环SDK offset。批次同时受行数和字节预算约束，单记录有独立保护预算。SourceSnapshot整文件不再套用旧64MiB JSON上限；原JSON/Android/RMFH限制保持。

分批消息仍调用共享BaseImporter._persist；消息、来源映射、批次清单、游标、计数和归档revision在同一Schema3事务内提交。取消/进程边界后按已确认游标恢复；已有归档在批次间改变时拒绝盲目恢复，可明确restart重新核对全来源且按来源ID去重。完整重复导入会重新核对记录，新增0、已归档事件算重复，不把上次已完成当作本次新写入。

这是明确的“逐批提交”模式，已提交部分保留；不能与旧整文件strict原子语义混淆，快照入口拒绝该选项。未知记录保留在快照，结果区分支持文本、归档重复、来源重复和隔离原记录，逐项满足源计数守恒。模式结果和恢复信息已接入桌面结果卡/详细报告；源码File导入可检测、预览和导入快照目录，预览只报告源数量，不伪造支持文本数。

## 可运行入口

```powershell
python -m cli --db "D:\archives\chat-v3.db" import-snapshot "D:\exports\selected-chat-snapshot" --batch-size 1000
```

未完成会话自动恢复；归档被改动后如要重新核对，显式加`--restart`。选择Schema3归档的桌面“全部电脑本地记录”使用快照路径；普通Schema2继续原有有界路径，不自动升级。桌面取消在当前批次保存完成后停止后续批次；原记录和已提交消息保留。

## 差距与方向调整

[WechatExporter](https://github.com/BlueMatthew/WechatExporter)的资料涉及多类型与增量导出，本阶段缩小了来源完整性、批次恢复和事件重复方面的缺口；其iTunes输入与本项目Windows库不同，不能互证版本/媒体支持。[固定来源项目](https://github.com/fanyuantaier/wechatauto-replica)的公开全文/媒体宣传不代替本应用验收；当前仅固定模块指纹和已登记SQL投影自建验证，真实选定会话全历史需另行实际验收。

下一P1首先按用户重点改善Codex使用界面：连接/登录/范围/提问的真实状态，未登录不能发问、失败可重试、清楚的会话范围、引用回查、复制/导出与便捷提问。之后增加检索及群聊/媒体的完整存储→展示→导出闭环。P0源码基础已逐单元完成，真实微信、DPI/其他机器/账号和发行包的验收边界继续保留，不因自建测试通过而标成完成。

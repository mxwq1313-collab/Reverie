## 交付清单

| 要求 | 结果 |
|---|---|
| 标准格式 | 完整 Draft 2020-12 JSON Schema、正常/空 JSON 与 CSV 示例 |
| 独立 Importer | BaseImporter、JSONImporter、CSVImporter、validator、import_report 与中间模型 |
| JSON / CSV | 自动映射用户、建立私聊、创建消息 |
| 数据校验 | 必填/未知字段、ID、引用、成员关系、类型、时区和日期、空数据、编码 |
| 报告 | 每次导入 JSON 报告，状态、分项计数、错误位置、重复数和耗时 |
| 去重 | UTC 固定微秒、原始内容与双方 ID 的 SHA-256；批内及跨批跳过 |
| 迁移 | 版本 1→2 升级前备份、逐级事务迁移、历史记录与失败回滚 |
| 浏览器兼容 | 四个前端资源与 v0.2.0 字节一致；导入后实际浏览器展示正常 |

不处理真实微信数据库、密钥、解密或备份格式。群聊和媒体为协议预留，当前能力明确拒绝，不静默丢弃。

## 适用范围

默认部分导入会保留合法用户及记录；严格模式用于任何错误都不能接收的场景。不同来源的身份合并依赖明确 external_id，CSV 同名用户需正确 namespace。相同双方、同一微秒、相同正文按要求视为重复。

本阶段提供第四阶段稳定边界：解析器返回标准 LoadedDocument，随后复用现有校验、映射、去重、事务和报告。当前不提供真实微信兼容性、媒体处理或数据库降级。

# 思绪 1.1.0 图片表情修复验收

2026-10-15；分支 `fix/sixu-real-media`。正式版本保持 1.1.0，原 `v1.1.0` 标签保留。可运行构建名称增加“媒体修复版”，提交 ID 和发行文件摘要见包内 `release_manifest.json`。

## 真实问题和解决方法

用户确认缺失发生在 1.1 重新点击一键读取后。实际检查发现，图片消息 XML 的 MD5 是 CDN 明文内容身份，本地加密缓存文件使用消息 packed_info 中的另一标识。失败样本按 XML 匹配不到，按 packed_info 可找到对应文件。现在仅在选定账号、会话的缓存目录内建一次索引，优先选真正存在的 packed_info 标识，再回退 XML。沿用独立解码层，不在消息解析中猜解未知加密格式。wxgf 预览转换和原始容器分别保存。

表情缓存实际位于账号的 `cache/YYYY-MM/Emoticon`。本机这批缓存多为不能直接按消息 MD5 匹配的非明文文件；目录存在不等于已恢复。现在补充该目录的明文资源匹配；仍失败时使用消息或已登记表情库中的官方 CDN 资源地址。按用户本次明确授权，桌面添加页默认允许，选择可持久保存；关闭后仅本地恢复。`capture_rich` 和控制器 API 的 `allow_cdn` 默认 False，工作进程仅接受显式布尔 True。

地址只允许精确登记的 `emoji.qpic.cn`、`mmbiz.qpic.cn`、`mmbiz.qlogo.cn`、`wx.qlogo.cn`、`vweixinf.tc.qq.com`、`wxapp.tc.qq.com`；每次重定向重新校验。保留来源 http/https 协议，不把 HTTPS 地址降级，不关闭证书验证。本次真实来源为 http，强制替换成 https 会失败；默认代理路径也曾返回 502。仅这类经过允许列表验证的表情请求使用独立直连 opener，系统和 Codex 代理没有改动。

每个资源限制 16 MiB、4000 万像素，单次最多 50 次网络尝试，开始新请求前检查90秒预算；只接受已声明 MD5 匹配的 GIF/PNG/JPEG/WebP。校验失败、资源过期或格式未知均显示未取得及类别，不将文字导入成功当作媒体成功。请求只取已有资源地址，不发送聊天正文，不记录资源 URL、密钥或原始私聊内容。获取步骤不运行模型推理。

## 界面与响应

回答生成提示为“千丝万绪…”和三个轮换圆点；完成、停止、失败时仍按原生命周期清除。用户在右、Codex 在左。Reconnecting 表示连接重试；本次媒体修复不等于外部网络永不重连。

按用户最后澄清，收回全面图标化。导航、检测账号、一键读取、导入副本、新建/打开归档、状态和错误详情保留文字；复制、保存、日期、目录选择等明确辅助操作保留矢量图标与可访问名称。鼠标停留或键盘聚焦显示说明。同时可见的不同辅助操作不复用图标：联系人加载、模型刷新与失败重试分别使用联系人、环形刷新与回转箭头；文件选择与目录选择分别使用文件与文件夹；查看归档与回到最新分别使用对话与向下定位。各主页面、来源两个标签页均做可见辅助图标唯一性检查。离线网页六项按钮保留文字，并有 title 和 aria-label。

去除切页前的 busy 拒绝及后台任务对导航的禁用；数据变更按钮继续互斥。图片摘要校验和 Pillow 解码移入两线程池，Tk 主线程只提交任务与创建 PhotoImage，过期页面任务不会写回新归档。缩略图缓存上限 64；未变消息和主题宽度复用排版。

同一台机器、同组 8 个真实媒体、各 3 次冷缩略图构建，主线程提交中位 76.046 ms → 37.978 ms；这不含全部图片加载完成或 OS 输入延迟。另一个 125 条合成文本、松绿主题、1240×820、10 次帮助返回聊天的基准为 47.38 ms → 44.28 ms，包含最少 40 ms 事件循环窗口。没有声称所有机器或所有页面已达到同一速度。

字号切换曾在Theme.update中强制update_idletasks，并重建全部配色样式、隐式改变全局继承字体，随后又做聊天重排、AI全文重新标记及重复本地化。现在按字号/字体、配色、语言和非视觉偏好分别更新；同主题不重复theme_use；字号不重建背景图像，字体描述按原始像素单位和角色映射并缓存。各控件使用预备的局部字体样式，隐藏主页面和标签页保留第一份旧字体映射，显示时直接应用最新值。字体或配色变化不重新写入AI对话；只在语言改变时翻译角色。聊天原文、选区、引用和归档字节保持。连续点击应用在90ms窗口内合并，关闭时取消尚未执行的应用。

同一125条合成记录、1240×820、设置页显示，4次字号变化、4次配色变化、3次无变化应用，分开记录设置回调和root.update完成时间。字号中位回调 2079.146 ms → 71.754 ms，总重绘 3574.412 ms → 1902.316 ms；配色回调 760.638 ms → 12.986 ms；无变化回调 727.875 ms → 4.497 ms。测试窗口透明，未测物理鼠标/显示器延迟。10ms定时心跳也显示首次字体载入/Windows绘制仍可能出现数百毫秒间隔，未声称完全消除所有卡顿。此优化保留实际字号应用，没有用保持旧字号换取计时改善。

全量发现并运行 740 项：739 通过、0 失败、1 项既有 Windows 创建符号链接权限跳过；管理 15/15。后端 332 项同进程，间接依赖 Tk 的 408 项逐例隔离；初始化窗口完成首轮布局后再执行原断言，没有扩大原网络等待上限。初次全量暴露联系人重建的属性误用，已修复并增加检查；旧测试要求读取期间不能切页，与本次需求冲突，已更新为允许导航且导入/导出保持锁定，事务取消检查保留。字号专项发现像素/点数混淆后已修复，并验证实际消息字体大小及原文选区。早期失败与最终回执均保留于本机构建目录。最后字体局部样式收尾后，相关界面与兼容性100项全部通过；包括主页面图标唯一性、主要动作文字、悬停、主题、字体与窄窗口。

## 使用与剩余边界

关闭旧版，打开本次修复版文件夹中的“思绪.exe”；保留同目录 `_internal`。在添加页依次检测账号、选择会话和条数，保持高级设置中的“从微信官方CDN补全缺失表情”选项启用，然后点击“一键读取（含图片/表情）”。悬停图标可查看完整功能名。要补老消息的图片，请在包含该消息的范围重新读取，来源 ID 去重会补齐附件；单纯打开旧库不能凭空补回原文件。

官方 CDN 失效、消息缺少可校验 MD5、本机没有对应缓存、未知专有编码以及未登记的转发内嵌附件仍可能无法恢复，详情会记录类别。合并转发的文本展开已验证；没有宣称全部转发内嵌图片或所有历史表情均可恢复。其他电脑、微信版本、DPI 与完整数万条历史未逐一验收。
